# 生成类工具模板体系统一 · 技术设计文档

> 版本：v1.0（2026-09-19）
> 来源：《用户体验优化建议》P2-10「生成类工具的模板体系统一」
> 状态：Phase 1 已实施，Phase 2~4 按版本排期

---

## 1. 背景与问题

应用现有 4 个生成类工具，各自独立实现了一套"模板"机制，仅底层导出管线（组件截图 → PixelMap → 保存相册/分享，`ShareImageUtil`）与历史存储（`CoverHistoryStore`，首图/生字卡共用）是复用的：

| 工具 | 模板数据 | 预览组件 | 参数编辑 | 导出规格 | 历史记录 |
| --- | --- | --- | --- | --- | --- |
| 公众号首图 | `CoverTemplate`（id/series/slots/palettes/fonts/seed） | 页内 layoutBuilder 按 layout 分发 | 槽位输入自写 | 900×383 固定 | `CoverHistoryStore` |
| 生字卡 | `CharCardTemplates` 常量类（尺寸/格型/字色/配色） | `CharCardPreview` | 尺寸/风格 chips 自写 | 1080×1080 / 1080×1440 | `CoverHistoryStore` |
| 文字转图片 | `TemplateInfo`（15 个扁平颜色字段+字体） | `ShareImageCard` | 文本域+高亮词自写 | 1080 宽多档 | 无（仅示例回填） |
| 词云生成 | 自有配置（形状/遮罩/颜色组） | Canvas 自绘 | 词语表/权重自写 | 1080² | 无 |

**具体痛点（含代码证据）**：

1. **配色选择 UI 三处近似复制**：`CharCardPage.PaletteSection()`（CharCardPage.ets:502）与 `CoverMakerPage.StyleEditor()` 内配色块（CoverMakerPage.ets:697-734）为 38px 圆底+14px 色块+44px 选中描边的同一套交互，仅描边色不同；
2. **选项 chips 组件反复手写**：`CharCardPage` 的 SizeChips/StyleChips（尺寸/格型/字色/拼音 4 组）与 `CoverMakerPage` 的字体 chips 均为 `Text + selected?accent:bg` 模式，每处 10~15 行；
3. **模板接入成本高**：新增一个模板/工具需整页手写（`CoverMakerPage` 845 行、`Md2PngPage` 1400+ 行），模板数据、参数面板、历史、导出无法只靠"配置"完成；
4. **跨工具交互不一致**：预览区位置、参数分组方式、配色/字体选择器样式各异，用户跨工具需要重新学习。

## 2. 目标与非目标

**目标**

- G1 抽象统一的模板协议（UnifiedTemplate），覆盖 4 个工具的现有能力超集；
- G2 沉淀共享参数组件（配色选择、选项 chips），先消除已确认的 UI 重复；
- G3 提供模板注册表（Registry），新模板以"数据 + 预览 Builder"注册即接入；
- G4 统一编辑页交互范式：上方预览 + 下方分组参数，跨工具零学习成本。

**非目标**

- 不重写预览渲染引擎（各工具预览差异大，强行抽象收益为负）；
- 不动导出管线与历史存储（已复用，保持稳定）；
- 不做云端模板商店（离线应用定位）。

## 3. 统一协议设计

### 3.1 分层架构

```
┌─────────────────────────────────────────────┐
│  页面层  CoverMakerPage / CharCardPage /    │
│          Md2PngPage / WordCloudPage          │  ← Phase 2~3 逐页迁移
├─────────────────────────────────────────────┤
│  共享组件层  PaletteSection / ChipRow /     │
│             SlotEditor(Phase 3)             │  ← Phase 1 已落地 2 个
├─────────────────────────────────────────────┤
│  协议层  UnifiedTemplate / TemplateSlot /   │
│          UnifiedPalette / ExportSpec        │  ← Phase 1 已落地
├─────────────────────────────────────────────┤
│  注册层  UnifiedTemplateRegistry            │  ← Phase 1 已落地
├─────────────────────────────────────────────┤
│  基建层  ShareImageUtil / CoverHistoryStore │  ← 已复用，不动
└─────────────────────────────────────────────┘
```

### 3.2 核心类型（`core/template/UnifiedTemplateModels.ets`）

```text
UnifiedToolKind      工具类别常量：cover / charcard / md2png / wordcloud
TemplateSlotKind     槽位类型：TEXT / MULTILINE / PINYIN / NUMBER / CHOICE
TemplateFontOption   字体选项：family + label

TemplateSlot         槽位定义：
                     id, label, kind, maxLength,
                     options?: ChipOption[](CHOICE 用),
                     autoFill: string('' | 'quote' | 'pinyin' | …内容推荐钩子)

UnifiedPalette       配色方案 —— 直接沿用 CoverPalette（已是事实标准，
                     bg/bg2/accent/title/sub/block/grid 七槽色）

ExportSpec           导出规格：label, designW/H, exportW/H

UnifiedTemplate      模板基类（各工具模板 extends 它）：
                     id, name, kind, series, slots[],
                     palettes: UnifiedPalette[], fonts: TemplateFontOption[],
                     exportSpecs: ExportSpec[],
                     defaults: Record<string, Object>(槽位默认值)

UnifiedToolDescriptor 工具描述：kind, title, subtitle, page, icon, color
```

**设计决策**：

- D1 `UnifiedPalette = CoverPalette`：首图/生字卡已共用它，词云的"颜色组"可映射到 `accent/title` 两个槽色，不新建类型避免三套色板并存；
- D2 槽位沿用首图的 slot 语义并扩展 `kind`：首图的 title/subtitle/quote… 即 `TEXT` 槽，生字卡的 chars 即带 `maxLength=12` 的 `TEXT` + `PINYIN` 联动槽，md2png 的正文即 `MULTILINE`；
- D3 `autoFill` 字符串而非回调：内容推荐（换一句/自动注音）由各页面实现，协议只声明"此槽可自动填充"的能力标记，保持数据类可序列化（历史记录/未来云端下发兼容）；
- D4 模板是 class 基类而非 interface：ArkTS 禁结构化类型，各工具模板必须显式 `extends UnifiedTemplate`，页面接收时类型安全。

### 3.3 注册表（`core/template/UnifiedTemplateRegistry.ets`）

```text
UnifiedTemplateRegistry
  +register(tool: UnifiedToolDescriptor, templates: UnifiedTemplate[])
  +allTools(): UnifiedToolDescriptor[]
  +toolOf(kind): UnifiedToolDescriptor | null
  +templatesOf(kind): UnifiedTemplate[]
  +templateById(kind, id): UnifiedTemplate | null
  -store: Map<string, ...>（静态注册表，进程内单例）
```

注册时机：各工具模块定义自己的 `XxxTemplateSet.ets`（数据文件），在 `UnifiedTemplateSets.ets` 集中调用 register（由 `Index.aboutToAppear` 显式触发注册，幂等；不用模块顶层副作用语句，规避 side-effect import 限制）。

## 4. 共享组件设计（Phase 1 已实施）

### 4.1 `components/template/PaletteSection.ets`

替代 CharCardPage/CoverMakerPage 中重复的配色选择块。

```text
@Component PaletteSection
  @Prop palettes: UnifiedPalette[]      配色列表
  @Prop selectedIndex: number           当前选中
  @Prop accentColor: string             选中描边色（生字卡 #D8231A / 首图 #2E6FD6）
  @Prop labelColor: string              标题色（随深色模式）
  @Prop title: string = '配色方案'
  onSelect: (index: number) => void     选中回调（替代 @Link，降低耦合）
```

视觉规格：38px 圆底 + 44px 选中描边不变；内部色点统一为 14px 圆点（borderRadius 7，原首图页样式；生字卡页原为 14px 方点 borderRadius 2，属有意统一的规格差异）。用户基本无感知。

### 4.2 `components/template/ChipRow.ets`

替代 4 组手写选项 chips（尺寸/格型/字色/拼音等）。

```text
class ChipOption { value: string; label: string }

@Component ChipRow
  @Prop label: string                   行标签（'尺寸'/'格型'…）
  @Prop options: ChipOption[]
  @Prop selected: string                当前选中 value
  @Prop accent / chipBg / chipText / labelColor: string
  onSelect: (value: string) => void
```

### 4.3 迁移结果

- `CharCardPage`：PaletteSection/SizeChips/StyleChips 改用共享组件，页面净减约 90 行；
- `CoverMakerPage`：配色块改用 PaletteSection（字体 chips Phase 2 随槽位编辑器一并迁移）；
- 行为不变：所有状态仍留在页面，共享组件纯展示 + 回调。

## 5. 实施路线

| 阶段 | 内容 | 风险 | 状态 |
| --- | --- | --- | --- |
| **Phase 1** | 协议模型 + 注册表 + PaletteSection/ChipRow + 两页迁移 | 低（纯 UI 去重，行为不变） | ✅ 本次交付 |
| **Phase 2** | 槽位编辑器 SlotEditor：按 slots[] 声明渲染输入组件（TEXT/MULTILINE/PINYYIN/CHOICE），首图页槽位区迁移 | 中（首图槽位有联动：换一句/自动注音/字数校验） | v1.3 |
| **Phase 3** | 生字卡/文字转图片整页接入协议（模板改为 extends UnifiedTemplate 并注册）；导出规格改读 ExportSpec | 中（历史记录 templateId 兼容） | v1.3~v1.4 |
| **Phase 4** | 词云配置映射为模板 + 新工具"配置即接入"指引文档；编辑页布局范式统一（上方预览+下方参数分组） | 高（涉及 Canvas 预览交互） | v1.4+ |

**兼容性红线**：

- 历史记录 `templateId`/`textsJson` 格式不变（已发布用户的历史可恢复）；
- 每阶段独立可发布，任一阶段回滚不影响其他工具。
