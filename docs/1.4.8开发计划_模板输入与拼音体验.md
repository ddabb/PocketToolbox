# 1.4.8 开发计划：模板输入定制与拼音体验

> 承接《1.4.7开发计划_代码质量优化.md》。1.4.7 已发版（1.4.7/1000027，02a3f37），模板批 5/6/7 与真机回归顺延至本版。1.4.8 聚焦四项用户新需求：对联上下联多输入、聊天泡泡头像上传、生字卡拼音选项式修正、其余模板输入优化。执行记录随开发滚动更新（§10）。

## 1. 背景与目标

3. 「比如聊天泡泡，又是否可以上传图片设置聊天头像呢」→ T12 聊天泡泡
4. 「其余模板能优化也得优化」→ 21 模板输入区全摸底（§2.2）

### 1.2 1.4.7 顺延项

- 模板批 5/6/7 精简（SignBoards / BigText / Simple）
- ReviewReminderUtil 对齐 CheckInReminderUtil 模式（欠账）

### 1.3 目标与非目标

目标：§1.1 四项 + §1.2 全部。
非目标：P2-2/P2-3/P2-4/P3-1/P3-2/Phase 4 重构项继续顺延 1.4.9+（§7）。

## 2. 现状与摸底

### 2.1 槽位系统现状

- 固定三槽 body/sign/tag + 水印开关（`CopyPosterModels.ets`：`CopyPosterSlot` 常量、`CopyPosterContent{body,sign,tag,watermarkOn,watermarkText}`）。
- 页面输入面板：换一句行（targets body）+ body TextArea + sign/tag TextInput；`onSlotChange` 仅处理三槽。
- 21 模板注册表全部 `slots=['body','sign','tag']`，无定制槽；`supportsPinyin=false` 共 7 个（T9/T10/T13/T14/T15/T16/T18）。
- 限制：单 body 槽无法表达「上联 + 下联」两段独立竖排文本；无图片输入通道。
- 历史持久化：`CoverHistoryRecord.textsJson = content.toJson()`，`fromJson` 以 `?? 缺省` 容错旧记录（watermarkOn 模式可复制）。

### 2.3 生字卡拼音现状

- `pinyinText` @State 由 `CoverContentUtil.autoPinyin` 自动生成；CharCardPage L717-759 TextInput 手输带调拼音，focus/change → `pinyinLocked=true`（char_pinyin_locked_label + 恢复自动 char_pinyin_auto）。
- 用户痛点：手输带调拼音（如 xué）需输入法切换/拼读声调，易错。
- **可直接复用的既有设施**（CoverMakerPage 已验证）：
  - `CoverContentUtil.syllables / replaceSyllable(pinyinText, index, value) / pinyinCandidates(ch)`（多音字全读音）；
  - `PinyinSyllableEditor` 交互模式（CoverMakerPage L600-669）：逐字 chips（字+当前音节）→ 点击展开候选读音 Flex → 点选应用并锁定；
  - ohosTest `Cover.test.ets` tc10/tc11 已覆盖音节 API。
- 生字卡单字模式 ≤12 字（`CharCards.MAX_CHARS`），句子模式 ≤32 字，chips 需 Flex 换行（CoverMaker 为 8 字 Row 不够用）。

### 2.4 T12 头像现状

- `avatarChar(c)` = tag 首字 fallback 'P'；`ChatAvatar(c, sizePx, bg, ch, color)` = Stack+Text 圆角方块（radius 0.21×size）。
- 头像出现 3 处：顶栏 61px（accent）、正文气泡行 55px（accent）、署名气泡 55px（block，sign 首字）。
- 无图片输入通道；导出图已把头像烘焙进 PNG（历史回看不受影响），历史再编辑走 textsJson（新增字段随 JSON 持久化）。

### 2.5 基础设施现状

- 历史：`CoverHistoryStore` filesDir/{cover,card,poster}_history + index.json，MAX 20 条，超限 unlink 最旧。
- 竖排内核：`PosterTypeset.layoutVertical(text, availHeightPx, maxCols, basePx, …)`（1.4.6 产物），T16/T18/T20 已用。
- 资源：poster_slot_body/sign/tag + hints 四语（utf-8-sig）；新键需 ×4 同步，check_strings 门禁 1258 键基线。
- 属性混淆已关（obfuscation-rules.txt，拼音字典教训），`pinyinCandidates` 运行时安全。

## 3. 方案设计

### 3.1 多输入控件框架（通用机制）

**模型层**（`CopyPosterModels.ets`）：
- 新增 `CopyPosterSlotDef { id, label: ResourceStr, maxLen }`（`CopyPosterCategory.name` 已有 ResourceStr 先例）。
- `CopyPosterTemplate` 新增 `customSlots: CopyPosterSlotDef[] = []`，`of()` 增可选尾参。
- `CopyPosterContent` 新增显式字段 `coupletUp/coupletDown`（T18 定制槽位值）；copy/toJson/fromJson 同步，`?? ''` 缺省兼容旧历史。存显式类型字段而非 Record extras：ArkTS 类型安全，JSON 兼容模式与 watermarkOn 一致。

**注册表**（`CopyPosterTemplates.ets`）：
- T18 条目：`customSlots=[上联(≤14), 下联(≤14)]`，defaults 增 `coupletUp='岁岁平安福常在'`、`coupletDown='年年顺意喜盈门'`（body 默认保留，作清空回退）。
- `CopyPosterTemplate` 新增 `supportsAvatar: boolean = false`（supportsPinyin 先例），T12 传 true。

**页面层**（`CopyPosterPage.ets`）：
- `customSlots.length > 0` 时：隐藏换一句行与 body TextArea，ForEach 渲染定制槽位 TextInput（label/maxLen 数据驱动）；值读写经 `slotValueOf(id)` / `onCustomSlotChange(id, value)` if-chain 映射到显式字段，editedSlots 记录防默认覆盖。
- 槽位标签语义化：页面侧 `slotLabelFor(template, slot): ResourceStr` if-chain（按模板 id 分支，缺省回退通用标签），不引入动态资源查找。
- hint 暂不逐模板语义化（§8-3）。

### 3.2 T18 对联上下联渲染（PosterFestival.ets RedCouplet）

- 分支：`coupletUp/coupletDown` 任一非空 → 新布局：右列=上联、左列=下联（传统右起阅读序），各单列竖排 `layoutVertical(text, availH, 1, basePx, …)`；两列全空 → 回退 legacy `coupletLayout(body)` 竖排多列（旧历史/旧默认兼容）。
- 横批（tag）与落款（sign）渲染不变。
- 验收：新输入导出正确；恢复 1.4.7 时代的 T18 历史记录渲染不回归。

### 3.3 T12 聊天头像上传

- `CopyPosterContent` 新增 `avatarUri: string = ''`（toJson/fromJson/copy 同步）。
- 页面：`supportsAvatar` 时输入区顶部增头像行——圆角缩略图预览（有图 Image / 无图占位）+「上传/更换」+「移除」（有图时）。
- 选图：`photoAccessHelper.PhotoViewPicker` 单选 → **立即拷贝入沙箱** `filesDir/poster_avatar/avatar_<ts36><ext>`（picker URI 短授权不可依赖）→ content.avatarUri=沙箱路径。移除=删文件+清字段。
- 渲染：`ChatAvatar` 增图片分支——avatarUri 非空渲染 `Image` 圆角方块（objectFit Cover），空则回退首字；顶栏+正文气泡行 2 处接图，署名气泡维持 sign 首字（v1 仅对方头像，§8-1）。
- 历史再编辑：restore 时 `fs.accessSync` 校验，失联回退首字；头像文件不做自动清理（§8-4）。

### 3.4 生字卡拼音选项式修正（CharCardPage.ets）

- 移除手输 TextInput 与 char_pinyin_locked_label 行（用户原话「而不是手输」，§8-2）。
- 新增逐字 chips 编辑器（复用 CoverMakerPage `PinyinSyllableEditor` 模式 + `CoverContentUtil` 既有 API）：
  - chips = 当前模式汉字序列（字 + 当前音节），`Flex(wrap)` 换行（≤32 字）；
  - 点击 chip → `pyEditIndex` 高亮 → 候选读音 Flex（当前值置顶 + `pinyinCandidates(ch)` 多音字全读音）；
  - 点选候选 → `pinyinText = replaceSyllable(pinyinText, index, cand)`，`pinyinLocked = true`（防 chars 变更时 autoPinyin 覆盖）；恢复自动按钮保留（char_pinyin_auto）。
  - 音节数与汉字数不符（旧手输遗留）→ chips 隐藏，只读展示 pinyinText + 恢复自动。
- 新增提示键 `char_pinyin_pick_hint`（点击汉字修正读音）×4。

## 6. 风险与对策

1. **旧历史兼容**：coupletUp/coupletDown/avatarUri 走 `?? ''` 缺省；T18 保留 body 回退分支；恢复旧记录专项验证。
2. **picker URI 短授权**：选中后立即拷贝沙箱，不持有 URI。
3. **模拟器相册无图**：验证前用模拟器相机拍一张或检查预置图；不行则 ADB 侧注入媒体库。
4. **chips 32 字布局**：Flex wrap + 固定最小宽度，截图验证。
5. **字符串门禁**：新键一次性 ×4 同步（zh/zh_Hant/ja/base，utf-8-sig），避免 check_strings 中间态失败。
6. **属性混淆**：保持关闭（拼音字典教训），`pinyinCandidates` 运行时安全。

## 7. 顺延与裁剪（→ 1.4.9+）

1.4.7 计划中的重构项本期不做，继续顺延：P2-2 Index 拆分（2083）、P2-3 GifMaker 拆分（2821）、P2-4 其余千行页（Md2Png/SudokuSolver/XiehouyuQuery/WordCloud/PdfTool）、P3-1 导出链路统一（ImageExporter/ImageSaveShareBar 仅 4 页接入）、P3-2 查询脚手架 + 三份弹层合并、Phase 4 规范固化。理由：1.4.8 聚焦用户新需求与模板收尾，重构带宽不足；白名单只减不增目标由批 5/6/7 承接。

## 8. 待确认问题（已裁定，可推翻）
