# 1.4.6 模板默认文案：按模板适配 + 切换跟随

> 状态：已实施（2026-10-15）。本文档改前为实施计划，改后即变更确认单，逐项勾选状态见 §6。

## 1. 背景与问题

**现象**：T5（LCD 像素屏）上出现「请你喝茶呀」（底栏运营商位）与「Hi，朋友」（顶部信号旁标签）——这两条是 T1 暖调标签卡的默认文案，与功能机像素屏气质完全不符。

**根因**（`CopyPosterPage.ets` `selectTemplate`，切换模板逻辑）：

```
现状：切换模板 = 保留全部已输入内容，仅当槽位为空时补新模板默认值
```

首次进入页面时内容为空 → T1 默认文案（body「欢迎来访公众号「随身工具宝」」/ sign「请你喝茶呀」/ tag「hi 朋友」）被填入；
此后无论切到哪个模板，这三个槽位都非空 → **其它模板自己的默认文案永远不会出现**，T1 的文案跟着走完全程。

同时 T5 自带的默认 body 是一条 60 字测试长文（「今天测试六十字内容，看屏幕会不会自动撑高…」），属开发期遗留，不可作为默认呈现。

## 2. 目标

1. **切换跟随**：用户**未编辑过**的槽位，切换模板时呈现**新模板自己的默认值**；
2. **用户内容保护**：用户**已编辑**（手动输入 / 粘贴 / 换一句 / 历史恢复）的槽位，切换模板时**原样保留**；已编辑但被清空的槽位视为「回到未编辑」，重新跟随默认；
3. **T5 定制**（用户指定）：底栏「请你喝茶呀」→「菜单」；顶部「Hi，朋友」→「5G」；
4. **各自模板用最适配的默认文案**：21 个模板默认文案逐一复核，气质与槽位渲染位置匹配。

## 3. 机制改动方案

**编辑追踪**（会话内，不落盘）：

- 新增 `editedSlots: Set<string>`（body/sign/tag）；
- 标记为「已编辑」的入口：`onSlotChange`（编辑器手动输入/修改，剪贴板填充 `onClipFill` 复用此管道自动覆盖）、`changeBody`（换一句）、`restoreFromHistory`（历史恢复，三槽全标）；
- 不标记的入口：`selectTemplate` 补默认值（默认值不是用户编辑）。

**切换规则**（重写 `selectTemplate`）：

| 槽位状态 | 切换模板后 |
|---|---|
| 未编辑过 | 取新模板默认值 |
| 已编辑且非空 | 保留用户内容 |
| 已编辑但已清空 | 取新模板默认值（延续原「空槽补默认」行为，避免空海报） |

**关键流程推演**：

| 场景 | 行为 |
|---|---|
| 首次进入（内容空） | T1 默认文案填入（与现状一致） |
| T1 → T5，从未编辑 | 三槽全部变为 T5 默认（body「信号满格…」/ sign「菜单」/ tag「5G」）——**本次核心修复** |
| T1 → T5，只编辑过 body | body 保留；sign/tag 变为 T5 默认 |
| 换一句后切模板 | 换来的句子保留（用户主动选择的内容） |
| 历史恢复后切模板 | 三槽全保留（历史即用户内容） |

缩略图横滑条继续用当前 `content` 实时渲染（1.4.5 决策不变）；机制只改「选中模板后 content 变成什么」。

## 7. 风险与回退

- 风险：习惯旧「内容全局跟随」的用户，切模板时未编辑槽位文案会变化。属本次需求预期行为；编辑过的内容不受影响。
- 回退：`selectTemplate` 恢复原「仅补空槽」逻辑即可，模板 defaults 文案可独立保留。
