## 2. 痛点分析：零付费归因（2026-10-28，本期立项核心）

### 2.1 漏斗模型与断点假设

商店转化链路：`曝光（搜索/推荐位） → 详情页浏览 → 付费下载（¥6 盲付） → 激活使用 → 评分/反馈`。零付费只证明链路在某处断裂，未定位断点。三种断点假设对策完全不同，**数据先行，M0 查证后再动模式**：

| 断点假设 | 症状（AGC 数据） | 对症方向 |
| --- | --- | --- |
| H1 流量病 | 曝光/浏览量本身极低 | ASO/素材/关键词（A4），模式切换收益有限 |
| H2 转化病 | 浏览量可观但付费下载 ≈ 0 | 付费墙是瓶颈（§2.2-1），乙/丙案 |
| H3 双病 | 两者皆低 | A4 + 模式切换并行 |

当前无任何漏斗数据留存，H1/H2/H3 无法区分——这本身是首要痛点（§2.2-5）。

### 2.2 分层归因

1. **模式层：盲付门槛（最可能主因，对应 H2）**。整包付费 = 安装前付费，用户在零试用、零评分积累（付费后无新用户 → 无新增评分）、零品牌信任（个人开发者无历史应用背书）三重条件下盲付 ¥6，转化趋零是可预期的——变现开发计划 v2.0 §6 风险表首条「盲付转化低：下载量/收入不及预期」已被现实证实。风险表当时对策「¥6 低价切入；优化 ASO；可先免费积累评分再切付费」中的前置项（先免费攒分）实际未执行，顺序反了。
2. **流量层：自然流量薄 + 付费标签二次压制（对应 H1）**。个人开发者零推广预算，仅商店自然流量；付费标签在用户付费心智未成熟的市场里进一步压低点击意愿（华为应用市场免费应用为主流消费习惯）。
3. **产品层：定位混杂稀释价值感知**。「国学查询 + 创意工具 + 实用计算」三合一（app_description.txt），应用名「解语珠玑」偏国学文艺，实质是工具箱（用户体验优化建议 §7-7 早年即指出名实分离）——商店页 15 秒内无法形成「这值 ¥6」的单一强价值点；各功能均有免费替代（系统级单位换算、免费数独、网页版词云/Markdown 转图），付费理由弱。
4. **反馈层：零付费 = 零新增 = 零反馈回路**。付费墙切断新用户进入后，产品失去使用反馈、评分积累、方向标数据三个引擎；功能型迭代（含 1.5.0 B1/B2 与本期候选）的边际收益随之趋零——**在零用户现实下，先修漏斗、后磨功能的优先级反转是本期核心裁定依据（§8-2）**。
5. **数据缺失：决策无据**。当前未留存 AGC 漏斗数据（曝光/浏览/转化/评分），无法区分 H1/H2/H3；后续每次模式调整也无基线可对照。M0-A1 为全案第一步。

### 2.3 出路候选矩阵（§8-1 裁定项）

| 方案 | 内容 | 成本 | 预期 | 关键约束与查证 |
| --- | --- | --- | --- | --- |
| 甲 保持付费优化运营 | ASO 素材重写 + 临时价格调整（AGC 支持促销价） + 等待验证 | 最低（纯管理侧） | 存疑：不动盲付根因，仅降门槛不拆墙 | 最低价格档与促销机制为 M0 查证项 |
| 乙 回免费重建漏斗 | 下架删除重发设为免费，重建「下载→使用→反馈→评分」漏斗，变现后置 | 管理侧操作 + 素材复审 | 恢复自然流量入口，为一切后续模式（含丙）积累用户与信任基线 | **AGC 规则：在架应用不支持更改付费情况，需下架并删除已上架应用、重新发布时设置**（官方「付费下载应用」文档原文）——操作层级（应用级/版本级）、评分评论与 APP ID 保留性、存量已装用户升级链路为 M0 查证项；零付费现状下应用历史资产损失趋零 |
| 丙 回免费 + IAP 功能解锁 | 乙 + IAP Kit 非消耗型商品「功能解锁」（基础免费试用，高级功能买断） | 中（权益管理模块 + 沙箱测试 + 真机验证） | 试用与变现兼得，长期最优 | IAP 单机应用可接入已查证（官方 FAQ）；模拟器不支持 IAP 须真机沙箱；须 AGC 开启应用内购买服务并重申请发布 Profile；服务费率与结算规则 M0 查证；**零用户下先做 IAP 无人购买，须以乙先积累用户为前提** → 本期不做代码，立 1.6.0 |
| 丁 矩阵 pivot | 主应用维持现状，资源转向四独立应用 | — | — | 四应用与主应用同持「个人开发者 + 买断制」假设（3066a95），主应用 ¥6 零买单 = 该假设首次实测失败，丁案是风险复制而非对冲，不建议 |

### 2.4 四应用矩阵联动声明

像素画工作室（¥12）/口算题卡（¥6）/Md转换器（¥6）/字帖生成器（¥6）四立项均为买断制独立应用。主应用零付费是「¥6 级买断 + 零品牌信任 + 零评分」假设的首次实测失败信号。**建议：四应用维持开发推进（复用资产与技术沉淀不浪费），但各 M0 的「AGC 付费应用流程查证」升级为「上架模式复审」——待主应用商业化验证（M0 数据 + §8-1 裁定执行结果）有结论后，四应用上架时点与模式再定**；至少在主应用跑通「免费漏斗 → 付费转化」任一环节验证前，不贸然上架四个同模式收费应用。

### 2.5 结论与建议

1. **M0 数据先行**：AGC 后台拉漏斗数据（曝光/浏览/下载转化/评分/评论），定位 H1/H2/H3，回填 §10。
2. **建议乙案（回免费）为主案**：付费墙已被实测证实为转化黑洞；回免费是唯一能同时恢复「流量入口 + 反馈回路 + 信任积累」的路径；零付费现状下重发的沉没成本处于历史最低点（无新增评分/评论可损失）。丙案为乙案跑通后的 1.6.0 演进方向，本期零代码。
3. **功能迭代让位**：B1/B2 及一切「打磨无用户消费的能力」类工作默认顺延（§8-2），带宽让给商业化验证与发版链路收口。
4. **四应用联动**：开发不停、上架复审（§2.4）。

## 3. 方案设计
