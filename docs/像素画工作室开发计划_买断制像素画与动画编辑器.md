# 像素画工作室开发计划：买断制像素画与逐帧动画编辑器（v1.0.0 立项）

> 立项：2026-10-19 ／ 形态：HarmonyOS 原生单 HAP 买断制应用 ／ 定价：¥12（首发限时 ¥8）
> bundleName：com.ddabb.pixelstudio ／ vendor：lgayy ／ 网络：零网络权限（全离线）
> 一句话定位：鸿蒙原生像素画 + 逐帧动画创作工具——图层 / 选区 / 帧动画 / PNG·GIF·精灵图导出，一次买断、无广告、无订阅、无账号。

## 1. 立项背景与产品定位

### 1.1 为什么是像素编辑器
- 付费意愿已被充分验证：桌面端事实标准 Aseprite 定价约 $19.99（国区约 ¥70），长期占据 Steam 工具类畅销榜；像素创作人群稳定（独立游戏开发者 / 像素画爱好者 / 儿童涂鸦入门），且以"作品产出"为目的，工具价值感知强。
- HarmonyOS NEXT 生态空缺：应用市场检索"像素画"，缺乏"图层 + 帧动画 + 完整导出链"的原生编辑器；类目先行者可获得搜索心智与首发权重。
- 买断制天然匹配：创作工具无内容运营、无服务端、无账号体系，全部价值在客户端本地——成本结构 = 一次性开发 + 版本维护，无持续运营成本压力。
- 可行性极高：核心 = 网格像素数据结构 + 图元光栅算法 + 逐帧合成 + 既有 GIF 编码内核移植（自有代码），全部为确定性算法，无 ML、无第三方服务、无内容版权。

### 1.2 与 PocketToolbox 的边界（买断价值独立声明）
| 维度 | PocketToolbox GIF 工具 | 像素画工作室 |
| --- | --- | --- |
| 输入 | 已有视频 / 图片 → GIF 转换 | 从零绘制像素作品 |
| 核心能力 | 编码与格式转换 | 画布 / 图层 / 选区 / 帧动画创作 |
| 用户群 | 转换需求者 | 创作者 |
| 功能重叠 | 无 | 无 |

工具箱用户没有任何理由认为"这个功能我买过了"——两者是**转码器与创作工具**的关系（类比：视频格式转换器 vs 视频剪辑软件）。GifEncoder 内核的源码级复用是工程可行性手段，不构成产品功能重叠。

## 2. 目标用户与核心场景

- 独立游戏开发者：制作 16×16 / 32×32 精灵与 4-8 帧行走动画，导出精灵图进游戏引擎（Cocos / Unity / Godot）。
- 像素画爱好者：临摹、原创、社区分享 PNG / GIF。
- 亲子场景：平板像素涂鸦（小调色板约束天然降低儿童上手门槛）。
- **P0 必须丝滑的核心场景**：新建 32×32 → 铅笔起稿 → 油漆桶铺色 → 复制 8 帧做走路循环 → 播放预览 → 导出 GIF 分享。全程不卡顿、不丢笔、误触可撤销。

| 竞品 | 平台 | 模式 | 弱点（即机会） |

1. **鸿蒙原生**：流畅手势、深色模式、平板双栏自适应、一次买断无广告无订阅；

3. **离线隐私**：零网络权限声明，应用详情页"不联网"即卖点。

定价锚点：Aseprite ¥70（桌面）→ 移动端买断 ¥12 心理账户成立；首发 ¥8 冲类目榜。

### 5.2 手势协议（P0 锁定）
- 单指 = 当前工具执行；像素拾取 = floor(画布逻辑坐标 / 缩放)；
- **双指 = 平移 / 捏合缩放**：指针数 ≥2 立即挂起工具且不产生笔触；落笔后第二指按下不取消当前笔触（防误触，判定时机 = 按下瞬间指针计数）；
- 长按画布 300ms 且位移 <8px = 吸管取色；
- 工具执行中滑出画布边缘 = 停笔（不做边缘自动平移，P2 视反馈再议）；
- 鼠标（2in1）：左键绘制、右键吸色、滚轮缩放、悬停像素 1px 描边高亮。

### 5.3 面板规格
- 图层面板：列表行 = 可见性 👁 + 缩略图 + 名称 + 不透明度滑杆；拖动排序用上下移按钮（P0 不做长按拖拽，避免手势冲突）。
- 帧面板：横向帧缩略条 + 当前帧描边高亮 + ＋/复制/删除 + 播放 ▶ + FPS 滑杆 + 洋葱皮 Toggle；播放时画布循环预览，任意触屏即停。
- 导出页：格式三选（PNG / GIF / [P1]精灵图）→ 参数（放大倍数 / FPS / 量化模式）→ 实时尺寸与预估文件大小 → 保存到相册 / 分享双按钮。
- 无障碍：全部图标按钮带 contentDescription；画布播报"X×Y 像素画布，当前工具 Z，缩放 N×"。

## 6. 技术方案

### 6.1 架构（核心 / UI 分离，核心 100% 纯函数可测）
```
entry/src/main/ets/
  core/                       ← 纯逻辑层（不 import ArkUI；hypium 直测）
    PixelDoc.ets              ← 文档模型: Doc{w,h, layers[], frames[], palette, activeLayer/activeFrame}
    PixelBuffer.ets           ← Uint8Array RGBA 封装: get/setPx/clone/copyRegion/blit
    Raster.ets                ← 图元光栅: line(Bresenham)/rect/ellipse(中点)/mirror 映射/笔刷 stamp
    FloodFill.ets             ← 扫描线泛洪填充（Int32Array 栈，无递归）
    Compose.ets               ← 图层合成: 自下而上（可见性+不透明度+洋葱皮），输出单帧 RGBA
    GifCodec/                 ← 移植 GifEncoder（自有代码）: LZW + 中位切分量化
    PxsFile.ets               ← .pxs 工程序列化（魔数+元数据+像素流，zlib 压缩）
    UndoStack.ets             ← 混合撤销栈（命令+快照，见 6.3）
  viewmodel/
    EditorSession.ets         ← @ObservedV2 会话状态: 工具/颜色/缩放/选区/dirty
  pages/
    ProjectListPage.ets       ← 工程列表/新建
    EditorPage.ets            ← 编辑器主页（布局 §5.1）
  components/
    CanvasView.ets            ← 画布渲染（§6.2）+ 手势
    GridOverlay.ets           ← 网格覆盖层 Canvas
    panels/                   ← LayerPanel / PalettePanel / FrameStrip / ExportPanel
```

### 6.2 渲染管线（关键技术点①：最近邻放大免算法）
- 像素真源 = 每层每帧一个 `Uint8Array(w*h*4)`（RGBA）；编辑操作只写这个缓冲。
- 渲染 = 合成活动帧全部可见层（含洋葱皮叠加）→ `image.createPixelMap(buffer, {size})` → `Image{ interpolation: ImageInterpolation.None, objectFit: Contain }` 显示——**最近邻放大由渲染引擎免费完成**，无自绘缩放循环。
- 局部刷新：落笔仅标记 dirty，合成后 `pixelMap.writeBufferToPixels(整帧)` 写回。实测预算（§6.5）：64×64 整帧 16KB 写回 <2ms、128×128 64KB <5ms——P0 整帧写回即可达标，不做逐行 dirty 优化（留作 P1 256 画布手段）。
- 网格覆盖层：独立 Canvas 组件叠加于 Image 之上，缩放 ≥8× 时按变换矩阵绘制 1px 网格线（拖动/缩放时重绘）；透明棋盘格为画布区背景（CSS 渐变实现，不占渲染循环）。

### 6.3 混合撤销栈（关键技术点②：内存封顶）
- 笔刷类操作（铅笔/橡皮/直线/矩形/椭圆/填充/镜像均视为笔刷类）：操作前保存**受影响层该帧**的完整快照 `Uint8Array`（128×128 极限 64KB）；
- 结构类操作（图层增删/排序/选区移动复制删除）：保存文档级快照（全部层帧引用计数，未变层共享缓冲——写时复制，实际增量 = 受影响层）；
- 栈深 100，LRU 淘汰；内存上限 ≈ 100×64KB = 6.4MB（128 画布满幅极限），64×64 常态 <2MB——可接受，无需命令差分（差分是 P1 优化项）；
- undo/redo = 快照交换 + 重新合成 + dirty 置位。

### 6.4 工程文件 .pxs
- 未压缩体 = 4B 魔数 `PXSP` + 2B 格式版本 + 8B JSON 长度 + JSON 元数据（尺寸/图层表/调色板/帧序/FPS）+ 各层各帧 RGBA 字节顺序拼接；
- 压缩：`@kit.CoreFileKit` zlib `compressFile` 临时文件往返（像素艺术高冗余，128×128×8 层×8 帧原始 4MB → 典型 <500KB）；
- 自动保存：编辑置 dirty → 30s 定时 + onHide/onBackPress 即时 → 写沙箱 `files/pixel/projects/{uuid}.pxs`（写临时文件后原子 rename，防半写损坏）；
- 加载容错：魔数/版本校验失败 → 列表标灰"文件损坏"，不崩溃；杀进程恢复 = 启动时对 dirty 工程提示恢复。

### 6.5 性能预算
| 指标 | 预算 | 达成手段 |
| --- | --- | --- |
| 64×64 落笔→显色 | <16ms | 单遍合成 + 整帧 writeBufferToPixels |
| 128×128 合成（8 层） | <8ms | 合成循环零分配（复用目标缓冲） |
| 泛洪填充 128×128 | <10ms | 扫描线 + Int32Array 栈 |

## 13. v1.0.0 验收标准（发布门槛）
1. `pixelCoreTest` ≥60 用例全绿；模拟器套件协议全绿；
2. 64×64 落笔→显色 <16ms、128×128 <33ms（Mate 60 Pro 实测）；
3. 32 帧 GIF 导出产物经 Pillow 独立解码逐帧一致；
4. .pxs 往返 1000 次无损坏；杀进程自动保存恢复 ≤30s 数据损失；
5. 深色/浅色 × 手机/平板 四象限截图走查；
6. AGC 提审通过。
