# 朗读功能体验优化（v1.3.2 需求）

> 基于 v1.3.1（versionCode 1000011 @ b7486c1）真机（HUAWEI Mate 60 Pro）+ 模拟器双端测试过程整理。
> 1.3.1 已修复并验证：分段只读标题（onComplete type=1 判定）、播放按钮状态异常、重复排队（queueMode 抢占）、init 超时兜底、清单增删改跨页即时刷新。
> 本文档聚焦测试过程中**实际走过的弯路**与暴露的体验断点，作为 1.3.2 版本开发内容。
> 每条建议附代码证据（文件:行号），优先级：P0（本版本必修）、P1（本版本应做）、P2（择机/长期）。

## 测试动线回顾（问题的来源）

真机完整走了一遍"新用户首次使用朗读"路径：

1. 诗词详情页点 📖 → 弹窗只有"暂无朗读清单，请先创建"和"取消"，**没有创建入口**
2. 被迫绕行：取消 → 我的 → 朗读清单 → + 新建清单 → 输入名称 → 创建 → 返回诗词页 → 再点 📖 → 选择清单，共 **7 步**
3. 进入播放页点 ▶ → 10 段连续朗读正常，但全程只有"朗读中"三个字，**看不到读到哪一句**
4. 暂停 → 恢复正常，但发现**恢复会重读当前句**（句首重启）
5. 模拟器（无小艺 TTS 引擎）上点朗读 → **静默等待 8 秒**才提示"朗读失败(-1)，请稍后重试"，且重试永远失败

## P0 建议（本版本必修）

### 1. 📖 弹窗"断头路"：无清单时没有创建入口

> **✅ 已完成（随 v1.3.1 发布，真机验证通过）**：诗词/歇后语详情页弹窗空态下提供"+ 新建清单"，就地输入名称创建并一步加入；空名提示与清单页一致；有清单时的选择流程回归正常。

**现状**：`PoemContentPage.ets:382-387`，清单选择弹窗在无清单时仅渲染"暂无朗读清单，请先创建"+ 取消按钮；`XiehouyuQueryPage.ets:1050` 同样的弹窗同病。创建入口只存在于`ReadingListPage.ets:251`（+ 新建清单）。

**影响**：新用户首次加诗的必经之路是死胡同，7 步绕行期间极易流失。这是新用户从"发现功能"到"用上功能"的唯一卡点。

**建议**：
- 弹窗空态下增加"+ 新建清单"按钮，点击就地弹出名称输入框（复用 ReadingListPage.ets:283 AddListOverlay 的交互），创建成功后直接将当前诗词加入新清单并关闭弹窗；
- 创建+加入一步完成，不打断用户当前上下文（停留在诗词详情页）。

**验收**：
- [ ] 无清单状态下，诗词/歇后语详情页 📖 弹窗内可直接创建清单并完成加入，全程 ≤3 次点击；
- [ ] 新建名称为空时提示"请输入清单名称"，与清单页行为一致。

## P1 建议（本版本应做）

### 2. 朗读进度不可见：播放页不显示诗文内容与分段进度

**现状**：播放页仅展示条目标题与作者行（ReadingPlayerPage.ets 列表行），正在朗读的分段文本、当前段/总段数完全不可见。朗读 10 段约 40 秒，用户只能听，无法预览将要读什么、读到哪了。

**建议**：
- 播放页增加当前条目的内容预览区，朗读时**高亮当前分段**并自动滚动（分段数据已有：TtsUtil 的 `segments` + `segmentIndex`，通过 onStateChange 或新增 onSegmentChange 回调对外暴露）；
- 顶部状态行补充"朗读中 3/10"式进度。

**验收**：
- [ ] 朗读过程中当前句高亮且随朗读推进；
- [ ] 暂停/恢复后高亮位置正确。

### 3. 暂停恢复为句级重启，长句丢失进度感

**现状**：`TtsUtil.ets:244-261` pause() 用 engine.stop() 实现，恢复时 `resume()` 从 `segments[segmentIndex]` 句首重读。CoreSpeechKit 无原生 pause/resume，此为折中实现，但词的长句可达 20+ 字，暂停在句尾时恢复整句重读，用户感知是"回去了"。

**建议**（按成本递增择一）：
- 方案 A（低成本）：分段策略细化——朗读分句在 `splitToSegments`（TtsUtil.ets:330）按'。'切分的基础上，超长句（>N 字）再按'，''；'切分为子段，使句级重启的粒度可控；注意子段间 queueMode 抢占可能带来的语气停顿，需真机试听；
- 方案 B（文案兜底）：暂停态提示"已暂停（将从本句开头继续）"，管理预期。

**验收**：
- [ ] 任一位置暂停后恢复，重读范围 ≤ 半句或用户有明确预期。

### 4. 无 TTS 环境的失败反馈：8 秒静默 + 无意义错误码

**现状**：`TtsUtil.ets:7` init 超时 8 秒；失败后 `ReadingPlayerPage.ets:49-51` 弹"朗读失败(-1)，请稍后重试"。在无 TTS 引擎的设备（模拟器、部分海外机型）上：点击后 8 秒无任何反馈，且"-1"与"稍后重试"诱导用户重试一个必然失败的操作（实测每次重试都要再等 8 秒）。

**建议**：
- 初始化超时与朗读中报错区分文案：超时提示"当前设备暂不支持朗读"，不引导重试；
- 超时时长从 8s 收紧至 5s（真机实测 createEngine 仅需 0.6s，5s 已有充分余量）；
- 超时后短时间内（如同一次页面停留）重复点击不再重复等待：直接复用失败结论，仅在退出重进播放页后重新探测。

**验收**：
- [ ] 模拟器上点击朗读 ≤5 秒出现"当前设备暂不支持朗读"；
- [ ] 连续点击不产生多次 5 秒等待。

## P2 建议（择机排期）

### 5. 朗读中屏幕自动锁屏

**现状**：前台朗读时无 keepScreenOn，屏幕按系统超时锁屏（朗读因 AVSession 后台模式继续，属可接受但体验割裂：用户看着诗文听，屏幕忽然黑了）。

**建议**：朗读态置 `window.setWindowKeepScreenOn(true)`，idle/paused 恢复 false。挂接点：ReadingPlayerPage 的 onStateChange 回调（ReadingPlayerPage.ets:42-45）。

### 6. 语速固定不可调

**现状**：`TtsUtil.ets:215-217` speed=1/volume=2/pitch=1 写死。跟读、背诵场景对 0.75x/1.5x 有实际需求。

**建议**：播放页设置入口 + Slider（0.5~2.0 档位），存 preferences，speak 时注入 speed。

### 7. "已加入清单"反馈弱

**现状**：`PoemContentPage.ets:182-183` 加入成功后仅 1 秒 toast 且弹窗直接消失，无"加入了哪个清单"的确认感。

**建议**：toast 时长提至 1500ms 并带清单名（"已加入「test」"）；或在 📖 按钮上加已加入角标（同诗词已在某清单时）。

### 8. 空清单进入播放页的空态（待确认）

**现状**：清单 0 项时从清单页点进播放页的表现未在本次测试中覆盖（实测清单始终有 1 项）。需补测：若为白屏/无效页面，给"清单为空，去添加内容"引导。

### 9. 逐句点读

**建议**：内容预览区（P1-2 落地后）支持点击任意句从该句开始朗读（`speakSegmented` 已支持任意起点，仅需暴露 `startFrom(index)`）。
