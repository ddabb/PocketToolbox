# Md 转换器开发计划：买断制 Markdown 多格式转换工具（v1.0.0 立项）

> 立项：2026-10-19 ／ 形态：HarmonyOS 原生单 HAP 买断制应用 ／ 定价：¥6（首发限时 ¥4）
> bundleName：com.ddabb.mdconvert ／ vendor：lgayy ／ 网络：零网络权限（全离线）
> 一句话定位：鸿蒙原生 Markdown 多格式转换器——md 转 JSON / YAML / Word / 思维导图，本地离线转换、文档不出手机，一次买断、无广告、无订阅。

## 1. 立项背景与产品定位

### 1.1 为什么是 Md 转换器
- Markdown 已成通用标记枢纽：笔记（Obsidian/思源）、技术写作（GitHub/README）、AI 输出（大模型默认产出格式）全面采用 md；跨格式交付需求高频——md 转 Word 交作业/归档、md 转思维导图做知识复盘、md 转 JSON/YAML 进数据管线。AI 时代 md 产出量爆发，转换需求处于增长曲线。
- 隐私痛点真实：主流网页转换器要求**上传文档到服务器**——笔记、工作文档、课程资料含敏感内容，"本地离线转换"不是营销话术而是刚需差异。
- HarmonyOS NEXT 生态空缺：应用市场检索 markdown/转换，缺乏原生买断应用；移动端该类目整体空白。
- 买断制天然匹配：纯本地算法工具，无内容运营、无服务端、无账号——成本结构 = 一次性开发 + 版本维护。
- 可行性高：核心 = 自研受控 MD 解析器 + 四个格式生成器（JSON/YAML/DOCX/思维导图），全部确定性纯函数，TDD 友好；**零第三方依赖**（无开源授权与移植摩擦），产物全部为自有资产可复用。

### 1.2 与 PocketToolbox 的边界（买断价值独立声明）
| 维度 | PocketToolbox 文字转图片 | Md 转换器 |
| --- | --- | --- |
| 方向 | 渲染向：文本 → 美化图片卡片 | 解析向：md 文件 → 结构化数据格式 |
| 输入 | 粘贴文本（卡片文案） | .md 文件（文件级） |
| 产出 | 模板装饰分享图（社媒向） | JSON / YAML / DOCX / 思维导图文件（办公/开发交付） |
| 用户动机 | 发圈/发帖好看 | 数据转换、文档交付、知识整理 |
| 功能重叠 | 无 | 无 |

工具箱用户没有任何理由认为"这个功能我买过了"——文字转图片不做任何结构化导出，本应用不做任何卡片美化；两者是"美化滤镜"与"格式转换器"的关系，介质相邻、职能完全不同。

## 2. 目标用户与核心场景

- 笔记用户（主力）：Obsidian/思源/Notion 导出 md → Word 交付归档、思维导图复盘。
- 学生：课堂笔记（md）→ Word 作业提交；课程大纲 → 思维导图复习。
- 开发者/技术写作者：README/技术文档 → JSON/YAML 数据处理、Word 评审。
- 办公族：md 会议纪要 → Word 归档流转。
- **P0 必须丝滑的核心场景**：文件管理器选 notes.md → 预览解析树 → 选"Word" → 生成 → 保存/分享。全程 < 10 秒、零上传、零权限。

## 3. 竞品与差异化

| 竞品 | 形态 | 弱点（即机会） |
| --- | --- | --- |
| 网页转换器（主流） | 免费 + 广告 | **文档上传服务器**（隐私硬伤）、广告、无离线、无批量体验 |
| Pandoc | 桌面 CLI | 极客向、无 GUI、无移动端 |
| Typora | 桌面买断 ¥89 | 无移动端、导出强但无思维导图、价格高 |
| 移动端转换 App | 少见 | 鸿蒙原生类目空白 |

差异化主张：
1. **本地离线**：文档不出手机（零网络权限技术保证）——对笔记/工作文档用户是决定性差异；
2. **四格式一站式**：JSON / YAML / Word / 思维导图（PNG + .mm/.opml），覆盖数据、办公、知识整理三类动机；
3. **买断 ¥6**：低于 Typora 一个数量级；
4. **批量**：多文件统一格式批量转换。

## 4. 产品定义

### 4.1 功能清单

**P0（v1.0.0 上架必备）**

| 模块 | 功能 |
| --- | --- |
| 输入 | 系统文件选择器选 .md 文件（DocumentViewPicker 多选）；粘贴文本快捷输入；最近文件/最近转换历史 |
| 解析 | 自研受控 MD 解析器（§6.2）：标题 h1-h6、段落、有序/无序列表（嵌套）、代码块、引用、表格、分隔线、粗体/斜体/删除线/行内代码/链接/图片/转义；**未知语法降级为原文保留（绝不丢内容）** |
| 转 JSON | 语义树序列化（文档→标题树/块节点/行内 run，schema 固定可测）；两种模式：标题层级树（默认）/ 平铺块列表 |
| 转 YAML | 同树受控 YAML 序列化（自研 emitter：块标量/缩进/受控转义），配置类文档直用 |
| 转 Word（.docx） | OOXML 生成：标题样式映射 Word 内置 Heading、正文、列表编号、表格、代码块（等宽字体+浅底纹）、引用块、粗斜体/行内代码/删除线 run、链接；Word 2007+/WPS 双端实测（§6.4）；**.docx 为目标格式（legacy .doc 二进制格式不做）** |
| 转思维导图 | 标题层级 h1-h6 → 树；应用内预览 + PNG 导出（3 主题：清爽/手账/暗夜）；.mm（FreeMind XML）/ .opml（大纲）文件导出（XMind 可导入） |
| 批量 | 多选 .md → 统一格式批量转换 → 逐文件保存（DocumentSavePicker）/ 系统分享 |
| 预览 | 源码视图（等宽）+ 解析树视图（层级大纲）双页签；转换结果格式化预览（JSON/YAML 高亮、思维导图渲染） |
| 历史 | 转换历史（源文件/格式/时间），一键重新转换 |
| 设置 | 深色跟随系统；关于页（买断说明：购买凭证 = 华为账号，卸载重装免费恢复）；版本号 |

**P1（v1.1.0，上架后 2-4 周跟进）**
- md → HTML 自包含单文件（CSS 内联）；md 表格 → CSV；XMind 原生格式（zip+JSON）；思维导图交互预览（节点折叠/展开）；DOCX 图片嵌入（md 内联图片打包进 docx media）。

**P2（需求驱动，视用户反馈）**
- md → PDF（A4 版面）；反向转换（JSON/YAML → md）；front-matter 解析与透传。

### 4.2 非目标（明确不做）
- 不做 md 编辑器（只转换不创作——"转换器"定位边界）；
- 不做云转换/在线服务（离线即核心卖点）；
- 不做 legacy .doc 二进制格式（无公开规范，仅 .docx）；
- 不做 md → 图片卡片美化（PocketToolbox 文字转图片域，重叠红线）；
- 不做订阅/广告/内购（买断制产品哲学）。

## 6. 技术方案

### 6.1 架构（核心 / UI 分离，核心 100% 纯函数可测）
```
entry/src/main/ets/
  core/                       ← 纯逻辑层（不 import ArkUI；hypium 直测）
    MdParser.ets              ← 自研受控 MD 解析器：块级 + 行内 → MdTree
    JsonOut.ets               ← MdTree → JSON（标题树/平铺两种模式）
    YamlOut.ets               ← MdTree → YAML（自研受控 emitter）
    DocxOut/                  ← MdTree → .docx：OOXML 生成器 + 最小 zip writer（STORE）
    Mindmap/                  ← TreeBuilder(标题树) / Layout(分形布局纯函数)
                              ←   / MmExport / OpmlExport / PngRender(drawing)
    HistoryStore.ets          ← 转换历史持久化（沙箱 JSON）
  pages/
    ConvertPage.ets           ← 选择/粘贴/预览/转换主流程
    MindmapPreviewPage.ets    ← 思维导图画布预览 + 主题 + 导出
    BatchPage.ets             ← 批量转换
    HistoryPage.ets           ← 历史
  components/                 ← 大纲树视图 / JSON·YAML 着色预览 / 进度遮罩
```

### 6.2 自研受控解析器（关键技术点①：降级不丢失）
- 目标语法 = CommonMark 实用子集（标题/段落/嵌套列表/代码块/引用/表格/分隔线 + 粗斜体/行内码/链接/图片/删除线/转义）——覆盖笔记与技术文档 95%+ 场景；
- **健壮性原则：未知/边角语法一律降级为原文文本节点**——转换器绝不允许丢内容，宁可保守不解析（与渲染器不同：渲染器丢样式可接受，转换器丢内容是事故）；
- 输出 MdTree 显式数据类：Doc{blocks[]} / Heading{level,inline[]} / List{ordered,items[]} / Table{rows[][]} / Code{lang,text} / Quote{blocks[]} / Para{inline[]}；inline = Text/Bold/Italic/Strike/Code/Link/Image 联合类型（显式继承实现，非结构化字面量）；
- 黄金用例集 ≥ 40：逐语法 + 嵌套组合 + 边角（列表内代码块、表格对齐、转义星号、CRLF/空行策略）；
- 回环性质测试：解析 → 收集全部文本 → 与原文纯文本超集断言（无损性证明）。

### 6.3 JSON/YAML 序列化
- JSON：schema 固定（版本号 + 元信息 + 树），两种模式（标题层级树/平铺块列表），快照测试；
- YAML：自研受控 emitter——仅对自有 MdTree 结构发射（块标量 `|`、固定缩进、受控转义白名单），不做通用 YAML 实现；黄金用例 + 与主流解析器（Python yaml.safe_load）交叉验证对账；
- 编码统一 UTF-8（无 BOM，与口算 CSV 的 BOM 策略相反——JSON/YAML 消费方为程序，BOM 反而致错；该差异写入实现要点）。

### 6.4 DOCX 生成器（关键技术点②：OOXML + 最小 zip）
- .docx = zip 容器 + OOXML；最小文档集：`[Content_Types].xml`、`_rels/.rels`、`word/document.xml`、`word/styles.xml`；
- 样式映射：h1-h6 → Word 内置 Heading 1-6（导航窗格可用）、列表 → numbering/列表段落、表格 → tbl 网格、代码块 → 等宽字体+浅底纹段落、粗斜体/删除线/行内码 → run 属性、链接 → 外部超链接关系（P0 文字+关系，图片 P1）；
- zip writer 自研（**STORE 无压缩模式** ~150 行：Local File Header + Central Directory + EOCD，CRC32 查表）——不依赖系统 zip API，docx 体积可接受（文本为主）；
- 实测矩阵（M2 验收门槛）：Windows Word 2016+ / WPS 桌面版 / WPS 移动版 / 永中? 任选前三逐一打开验证样式；
- XML 良构性：转义（`<>&`）、命名空间声明齐全——测试解包断言。

### 6.5 思维导图（关键技术点③：布局纯函数 + 渲染）
- 树构建：h1-h6 → 层级树（无标题文档 → 单根 + 段落首行摘要节点）；同级节点过多合并策略（>12 子节点折叠提示）；
- 布局：经典左右分形 tidy tree（左右两半各一列子树，节点矩形两两不相交、父节点纵向居中于子节点范围）——**纯函数输出坐标，黄金快照 + 不相交不变量测试**；
- 渲染：drawing（@ohos.graphics.drawing）画布：圆角节点 + 贝塞尔连线 + 3 主题配色 → PNG 导出（ImagePacker）；画布尺寸自适应内容 + 4K 上限保护；
- .mm（FreeMind XML）/ .opml（大纲 XML）：字符串序列化，XMind/FreeMind 导入实测。
