## 二、P0 建议（下个版本应修）

### 1. Tab 切换会清空导航栈，用户浏览进度丢失

**现状**：`Index.ets:415-429`，Tabs.onChange 中对三个栈执行 `homeStack.clear()` / `toolStack.clear()` / `mineStack.clear()`。

**影响**：用户在工具 Tab 进入「数独求解 → 拍照识别」等深层流程时，误触底栏切到首页再切回，整个流程被重置。工具类 App 的核心场景就是"进来用完就走"，中途丢状态是最伤体验的失效模式之一。

**建议**：
- 保留各 Tab 的 Navigation 栈，切换 Tab 时不清空；首次进入 Tab 才初始化栈；
- 若担心内存，可在栈深超过 N 层时才做裁剪，而不是无条件清空。

> **✅ 已完成（v1.2.0）**：`Index.ets` Tabs.onChange 现仅切换 `currentTab` 并同步 AppStorage 栈引用（Index.ets:532-543），三栈均已保留，不再调用 `clear()`。

### 2. 图标体系混乱：emoji 与 SVG 混用，且存在 ❓兜底

**现状**：
- 底部 Tab 使用 emoji 图标（Index.ets:401/406/411：🏠🔧👤）；
- 首页三大入口混用 emoji（🌸📖）与 SVG（mine_xiehouyu）（Index.ets:478/509/540）；
- 创意工具格中词云/文字转图片/首图/生字卡用 emoji，GIF/数独用 SVG，无 icon 时兜底渲染 ❓（Index.ets:663-684）；
- 不同机型、不同系统字体下 emoji 渲染差异明显，且 emoji 无法跟随主题色。

**建议**：
- 统一为一套矢量图标资源（项目已有 `unit_gcd_lcm`、`creative_gif` 等 SVG，补齐缺口即可），Tab 栏同样替换为可着色的 SVG + 选中态变色；
- 移除 ❓兜底分支，ToolItem 构造时 icon 必填，缺失在开发期报错而非线上露出；
- 顺带收益：读屏软件对 emoji 的朗读是"扳手表情"之类的噪音，替换 SVG 后可配 accessibilityText。

> **🟡 基本完成（v1.2.0）**：底栏已换 SVG 资源并支持选中变色（`tab_home`/`tab_tools`/`tab_mine`，Index.ets:518-528 + TabBarItem fillColor）；首页三大入口已用 SVG（`home_poem` 等）；工具格 ❓ 兜底已移除。**残留**：GifMakerPage 模式卡片仍有 '🕘' emoji 装饰（GifMakerPage.ets:1716；贴纸/表情面板中的 emoji 属内容素材，不计）。

### 3. 深色模式下 214 处硬编码颜色，存在对比度失控风险

**现状**：pages 目录下 214 处 `#xxxxxx` 形式的硬编码颜色（如 Index.ets:684 `#2d7d4618`、AchievementPage.ets:1007 `#27ae60`）；项目虽有 `resources/dark` 目录，但硬编码颜色不会随深色模式切换。

**影响**：深色模式下浅色卡片底、深色文字等组合可能出现低对比度、文字"消失"等问题。工具类应用晚间使用比例高（睡前阅读、数独等场景），深色模式是高频路径。

**建议**：
- 用脚本把硬编码色值收敛到 `app.color.*` 资源，为每个颜色补充 dark 变体；
- 优先处理高频页面（首页、工具页、数独、生字卡）；
- 验收标准：系统切换深色模式后全页面走查一遍，对比度满足 WCAG AA（正文 4.5:1）。

> **✅ 基本完成（v1.2.1 后全量收敛）**：已完成对比度专项修复——资源色加深、新增 `on_accent_text`（commit 1b9a342），我的收藏"全部"标签深色白底白字修复（v1.2.1，新增 `tab_selected_bg`）。随后完成全量收敛：新增 34 个 base/dark 同名色资源（`brand_blue`、`char_accent_red`、`primary_indigo(+bg/_soft)`、`warning_orange/amber(+tint)`、`success/danger/info(_bg/_tint)`、`sudoku_*` 棋盘色、`board_cell_bg(_alt)`、`border_soft`、`editor_*` 编辑器五件套等），并将 pages 下全部 UI 硬编码色替换为 `$r('app.color.*')`（SudokuSolverPage 54 处、CoverMakerPage 25 处、CharCardPage 17 处、Timezone/DailyChallenge 各 16 处、WordCloud 8 处等，共 18 个文件）；共享组件 ChipRow/PaletteSection/ImageSaveShareBar 的颜色 prop 已改为 `ResourceColor`；选中态白字统一 `on_accent_text`（深色自动反转为深字）。**刻意保留硬编码**（内容/导出与设计需要，不随深色切换）：词云字体色与导出画布配色、首图/生字卡模板色、GIF 贴纸与文字覆盖物、各工具品牌 accent（Index ToolItem/GifMaker ModeCard/UnitConverter 分类色/成就徽章色）、遮罩 `#99000000`/`#00000080` 与阴影、时区夜间卡片 `#2c3e50` 深夜主题。**验收**：深色全页面代码走查通过（每个替换点均有 dark 变体），真机深色视觉走查待发版前抽查。

## 三、P1 建议（近期规划）

### 4. 工具 Tab 缺少「搜索」与「最近使用」

**现状**：工具页按「创意工具 / 数学计算 / 单位换算」三段平铺（Index.ets:735-742），无搜索框，无使用记录。随着 1.1.0 新增首图制作、生字卡，工具总数已超过 15 个，且单位换算类目还在持续增多。

**影响**：高频用户每次都要滚动寻找常用工具；新工具被埋在列表里，发现性差——这直接影响 1.1.0 两个新功能的曝光转化。

**建议**：
- 工具页顶部增加搜索框（按名称/副标题模糊匹配即可，数据量小无需索引）；
- 增加「最近使用」行：记录最近 4-8 个工具的打开时间，置顶展示；
- 首页也可增加一个紧凑的「最近工具」入口，把内容 Tab 与工具 Tab 打通。

> **✅ 已完成（v1.2.0）**：工具页搜索框（Index.ets:822 `搜索工具`）+ 搜索结果分区（:836）+ 最近使用分区（:849）；首页新增 `QuickToolsRow` 最近工具横滑行（:586/:721-746）；新增 `RecentToolsUtil` 记录使用（loadRecent/recordUse，取前 4 个）。三个子项全部落地。

### 5. 新功能的「历史记录」发现性不足

**现状**：首图制作已实现历史存储（core/cover/CoverHistoryStore.ets），生字卡无历史概念。

**建议**：
- 首图制作页把「历史作品」入口在页面主流程中露出（而不是藏在设置里），支持一键重新编辑；
- 生字卡可增加「最近生成」记忆（最近输入的生字串），家长/老师场景下重复修改同一批生字的频率很高；
- 所有生成类工具统一「生成 → 预览 → 保存/分享 → 下次可再来」的闭环。

> **🟡 基本完成（v1.2.0）**：首图/生字卡/GIF 均已有「最近制作」主流程入口（CoverMakerPage.ets:741、CharCardPage.ets:709、GifMakerPage.ets:1716）且支持点击 `restoreFromHistory` 一键恢复再编辑（CoverMakerPage.ets:271、CharCardPage.ets:205）；生字卡历史记录可还原生字串。**未完成**：词云、文字转图片无历史记录，"所有生成类工具统一闭环"未达成。

### 6. 每日复习卡的抽取池过小导致重复

**现状**：`Index.ets:224-242` loadReviewItem 优先从诗词收藏中抽取，收藏总数少时（如只有 2-3 条）每天看到的复习内容高度重复。

**建议**：
- 引入已展示去重队列（最近 7 天展示过的不再出现，池子耗尽再重置）；
- 收藏不足时回退到「每日诗词」池而不是任意收藏，保证内容新鲜度。

> **🟡 基本完成（v1.2.0）**：7 天去重队列已实现——`loadReviewShown` / `isRecentlyReviewShown(7天)` / `recordReviewShown`，池子耗尽自动重置（Index.ets:329-343，StickinessUtil）。**未完成**：收藏不足时的回退仍是"全量收藏"而非"每日诗词池"（Index.ets:328）。

### 7. 首页头部占屏过高，且品牌与定位需要平衡

**现状**：首页/工具页/我的页顶部均为 40px emoji + 22px 标题 + 13px 副标题的大头部（Index.ets:456-471、718-732）。首屏黄金区域约 120px 用于静态装饰。另外应用名为「解语珠玑」（AppScope string.json），但产品是"口袋工具箱"型混合应用，首页完全看不到工具入口。

**建议**：
- 头部精简为一行标题（或滚动时折叠成吸顶小标题），释放的首屏空间给签到卡和每日内容；
- 首页底部增加「快捷工具」横滑行（复用最近使用数据），让工具用户不必每次切 Tab。

> **✅ 已完成（v1.2.0）**：头部已精简为单行标题+右对齐副标题（Index.ets:573-584，无 40px emoji）；首页顶部新增 `QuickToolsRow` 最近工具横滑行（Index.ets:586）。

## 四、P2 建议（长期演进）

### 8. 无障碍（Accessibility）基础建设

- 当前交互元素普遍未设置 `accessibilityText`/`accessibilityDescription`，emoji 图标替换后应统一补齐；
- 工具格图标触控区 56×56 达标，但部分小按钮（刷新、关闭）建议走查一遍 48vp 最小触控标准。

> **🟡 部分完成（v1.2.0）**：底栏 Tab、最近使用、回到今日推荐等关键节点已补 `accessibilityText`（TabBarItem Index.ets:565，全项目 11 处）。**未完成**：交互元素全面覆盖、小按钮 48vp 触控走查。

### 9. 每日内容的「刷新」交互升级

**现状**：换一首是随机 offset（Index.ets:258-271），刷新后无法回到当日推荐，也没有"不感兴趣"反馈。

**建议**：增加刷新历史（可回退）、按朝代/类型偏好加权（与成就/挑战体系联动，形成个性化闭环）。

> **🟡 部分完成（v1.2.0）**：「回到今日推荐」已实现——诗词/成语/歇后语刷新后可一键回到当日推荐（`backToDailyPoem` 等，Index.ets:365-378，入口带 accessibilityText:1233/1294/1350）。**未完成**：刷新历史多步回退、按偏好加权。

### 10. 生成类工具的模板体系统一

词云、文字转图片、首图、生字卡各自实现了一套模板数据（CoverTemplates、CharCardTemplates 等）。长期看：
- 抽象统一的模板协议（预览组件 + 参数面板 + 导出），新工具接入成本从"一页一写"降为"配置模板"；
- 顺带统一四者的编辑页交互范式（左侧预览 + 右侧/底部参数），降低跨工具学习成本。

> **🟡 Phase 1 完成（v1.2.0，commit a196517）**：统一协议基类与注册表已落地——`core/template/UnifiedTemplateRegistry` + `UnifiedTemplateModels`（统一模板基类）+ `UnifiedTemplateSets`（词云/文字转图片/首图/生字卡 4 工具已注册），配色/选项 chips 共享组件已抽取，生字卡与首图页已迁移。后续阶段见《模板体系统一设计文档.md》。

### 11. 空状态与错误提示文案人格化

已有 ErrorState 组件，但工具类页面的空状态多为纯文字。建议统一空状态插画 + 引导按钮（如词云页空状态直接给「粘贴示例文本」一键操作），把空状态变成功能演示机会。

> **🟡 部分完成（v1.2.0）**：词云「示例」一键填充（WordCloudPage.ets:151/646）、Md2Png「Markdown示例/文本示例」（Md2PngPage.ets:940/951）、数独三种格式示例（SudokuSolverPage.ets:909-927）均已落地。**未完成**：统一空状态插画与引导规范。
