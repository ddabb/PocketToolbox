#### 2.1.2 根因 B：取消 5 档硬编码阶梯（全量接管字号）

`bodyFont()` 旧阶梯（第 103-123 行原文；`availWidthPx <= 0` 时走这条，即未迁的 7 个模板）：

```
普通分支（big=false）
  n <= 8   → basePx
  n <= 16  → basePx × 0.80
  n <= 32  → basePx × 0.62
  n <= 60  → basePx × 0.48
  else     → basePx × 0.38

大字分支（big=true）
  n <= 4   → 150
  n <= 8   → 112
  n <= 16  → 80
  else     → 52
```

三个硬伤：
1. **不感知容器宽度**——同样 20 字，T1 可用宽 760 与 T8 的 298 差近 2.5 倍，字号却一样；
2. **不感知行数预算**——三种比例宽度相同、高度不同，行数上限 8 / 12 不同；
3. **断点骤降**——32→33 字从 0.62 掉到 0.48，60→61 字从 0.48 掉到 0.38。

**迁移要求**：

1. **14 个已接内核模板**：复核可用宽参数是否与实际容器一致。当前 T8 用 298、T14 用 540，需实测是否含 padding 误差（T8 是最窄容器，最容易顶格）；T5 660 / T7 728 一并复核；
2. **A 类竖排 3 模板**：Phase 0 锁定 `layoutVertical` 方案后，替换私有分档（T16 `solarBodyPx` / T18 `coupletBodyPx` / T20 `boldBodyPx`）；
3. **B 类 4 模板**：先抽出主文案为 `BodyBlock`，再接内核，装饰字号保持不动；
4. **保留 `bodyFont()` 原签名作适配层**（`availWidthPx <= 0` 时行为与优化前完全一致），21/21 迁移完成 + 二期回归稳定后再删旧分支（列入 §3 非目标）；
5. **内核返回设计稿 px，渲染前必须经 `f()` 缩放**——`bodyFont` 第 97-99 行已有此处理并写了注释（漏掉会把字号当 fp 用，放大约 900/previewWidth 倍，把署名挤出画布），迁移时**不得绕过 bodyFont 直接用 `layout.fontPx`**。

**内核算法准入门槛**（1.4.5 踩坑，必须先在 Python 复刻跑通再写 ArkTS）：

| 用例集 | 内容 |
|---|---|
| 字数扫描 | 0 / 1 / 8 / 12 / 16 / 20 / 24 / 32 / **33** / 40 / 50 / 60 / **61** / 120 字（重点验 32→33、60→61 两处旧阶梯断点） |
| 容器宽度 | **298**（T8 最窄）/ 540（T14）/ 760（T1）/ 900（满宽） |
| 行数预算 | 3 / 5 / 8 / 12（方图 8、竖图 12；模板另有 3 / 4 / 5 覆盖值） |
| 期望曲线 | T1 base=72 下：4字72 / 8字72 / 12字68 / 16字64 / 20字61 / 24字58 / 32字53 / 40字47 / 50字45 —— **无骤降** |
| 已知踩坑 | 内核第一版因"宽度约束按整篇单行收缩"导致 8字72 → 16字47 骤降。修法：`widthFloor = min(availWidthPx/2, basePx)`，宽度只保证"一行至少放得下 2 个字"，其余交给折行 + 行数预算决定是否继续缩 |

#### 2.1.3 根因 C：截断提示统一

2. `poster_truncated_hint` 三语已存在，无需新增键；

4. 「已省略 N 字」的字数来源是内核 `truncatedChars`，不另算，避免两处口径不一致。

### A.1 PDFKit / pdfService（1.4.5 真机实证）

| 项 | 结论 |
|---|---|
| 单位 | pt；A4 = 595×842pt；px→pt 按 72/96 换算（`PdfComposer.pxToPt`） |
| 建页 | `createDocument(w,h)` **自带初始空白页**，内容插完必须 `deletePage(inserted, 1)` |

| API 起始版本 | pdfService 5.0.0(12) < 工程 `compatibleSdkVersion` **6.0.0(20)**（1.4.6 评论功能已升），**无 API 守卫负担** |

### A.4 算法改动纪律

1. **算法先在 Python 复刻跑边界用例，再写进 ArkTS**——1.4.5 内核第一版因宽度约束写错导致 8字72 → 16字47 骤降，凭感觉定系数必踩；
2. **保留旧签名做适配层**（`bodyFont(basePx, big, availWidthPx=0, maxLines=0)`），未传宽度时行为与优化前完全一致，让 21 个 Builder 分批迁移、任一中途状态都可编译；
3. **内核返回设计稿 px，渲染前必经 `f()`**——漏掉会放大约 900/previewWidth 倍；
4. **`LengthMetrics` 不是全局声明**，工程内无人这样用，别贸然引入；网格用 `Row + justifyContent(SpaceBetween)`。
