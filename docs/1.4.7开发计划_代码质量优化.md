# 1.4.7 开发计划：代码质量优化（大文件拆分与重复收敛）

> 状态：**§9 五项已全部裁定（2026-10-15，见 §10），Phase 0 / Phase 1 已完成**。基线日期：2026-10-15，前置：1.4.6 已收官推送（`4d27df4`）。
> 度量口径：`scripts/code_stats.py`（Phase 0 已交付，物理行=IDE 行号，含空行注释）。

## 1. 背景与目标

1.4.4→1.4.6 连续三期功能迭代后，工程主体达 **128 个 .ets / 53,320 行**，其中 **41% 的代码（21,788 行）集中在 10 个千行大文件**里。风险已经显性化：

- **Index.ets**（首页）近 75 天 **28 次提交**、单 struct 2,083 行——全应用回归面最大的文件同时也是改动最频繁的文件；
- **SudokuPixel.ets** 5,657 行（churn 24），类型定义、数字模板、棋盘检测、投影拟合混在一个文件，无 struct 无分层；
- **CopyPosterPreview.ets** 3,390 行、41 个 @Builder——1.4.6 计划的 Phase 3（根因 D 装饰层/内容层分层）尚未开工，若不合并安排将面临同文件二次大改；
- 五个编辑器页各写一套导出/保存/分享逻辑，查询三页同构脚手架复制粘贴；
- 核心纯算法（排版内核 / GIF 编解码 / PDF 合成 / 备份兼容）**测试覆盖为零**（ohosTest 现仅覆盖 sudoku OCR / CharCard / Cover 冒烟），重构无安全网。

**本期目标**（全部为行为零变化的结构重构）：

1. **度量先行**：体量统计脚本入库，每阶段前后可比；
2. **大文件拆分**：>1000 行文件 10 个 → **≤2 个**（终态 1：SudokuPixel 门面保留 recognizeDigit 整段，见 §10 P2-0 执行记录）；
3. **重复收敛**：导出链路、查询页脚手架、详情弹层三处统一；
4. **测试安全网**：核心纯函数模块 ohosTest 从 0 起步，先于拆分落地；
5. **护栏固化**：行数白名单机制（只减不增）+ 三语资源一致性校验脚本。
