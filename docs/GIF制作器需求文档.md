## 1. 背景与目标

### 1.1 背景

口袋工具箱的创意工具分类目前已有词云生成、文字转图片、数独求解三个工具，均围绕"输入内容 → 生成作品 → 保存/分享"的模式。用户在社交、教程制作、表情包创作等场景下有制作动态 GIF 的需求，而系统相册不提供该能力，第三方应用普遍存在广告多、导出水印、体积臃肿等问题。

### 1.2 对标产品分析

对标一款已上线的动图制作产品，其核心能力与本产品规划对照如下：

| 对标产品功能 | 本产品对应规划 | 优先级 |
|-------------|--------------|--------|
| 手机/电脑视频转 GIF | 视频转 GIF（仅支持本机视频，见差异说明） | P1 |
| 多张照片合成 GIF | 图片合成 GIF | P0 |
| GIF 动图编辑（二次加工） | GIF 编辑器（拆帧后复用合成编辑能力） | P1 |
| 调整 GIF 播放速度 | 全局倍速 + 帧时长调节 | P0 |
| 添加贴纸 | 贴纸素材库 | P1 |
| 添加文字（多种颜色） | 文字叠加（色板 + 自定义颜色） | P1 |
| 自定义制作 GIF | 尺寸/时长/循环次数等参数自定义 | P0 |
| 删除自己制作的 GIF | 制作历史管理（含删除） | P1 |
| 播放模式：倒放、倒放后正放等 | 播放模式：正放 / 倒放 / 来回 | P1 |

**与对标产品的差异说明：**

1. 对标产品支持"电脑上的视频"，本产品为纯手机端应用，仅支持本机（图库/文件）视频，电脑视频需用户先行传输至手机；
2. 本产品坚持零权限申请与纯本地处理，导出无水印。

### 1.3 目标

提供一款纯本地运行、无水印、操作简单的 GIF 制作工具，功能覆盖"图片合成、视频转 GIF、GIF 二次编辑"三条链路：

- 用户在 1 分钟内完成"选图 → 排序调参 → 预览 → 导出"完整流程；
- 导出的 GIF 体积可控、画质可接受，可直接保存到系统图库或分享给其他应用；
- 对标竞品核心功能（速度、倒放、贴纸文字、历史管理）全部覆盖；
- 与现有工具页风格一致，作为创意工具的第 4 个入口接入。

### 1.4 非目标（本期不做）

- 不做云端合成，所有处理均在端侧完成；
- 不做跨设备传输（电脑视频直连）；
- 不做 GIF 压缩/优化专项工具、不做 GIF 转视频。

| 编号 | 场景 | 描述 |

## 4. 交互与 UI 需求

1. 页面结构：首屏模式选择（图片合成 / 视频转 GIF / 编辑 GIF）→ 进入编辑页后自上而下：预览区 → 帧管理区 → 参数区（速度/播放模式/尺寸/画质）→ 叠加层（贴纸/文字）入口 → 底部"生成 GIF"主按钮，风格与 `WordCloudPage`、`Md2PngPage` 保持一致（卡片式分区、圆角、页面背景色复用 `app.color.page_background`）。
2. 空状态：未选素材时预览区显示引导插画与对应模式的"选择素材"按钮。
3. 主按钮在帧数 < 2 时置灰不可点；导出进行中变为"取消"，防止重复点击。
4. 贴纸/文字处于选中态时显示删除角标与编辑角标，空白处点击取消选中。
5. 所有提示统一使用 ToastUtil / 二次确认弹窗，文案为简体中文。

## 5. 非功能需求

| 类别 | 指标 |
|------|------|
| 性能 | 20 帧 480P GIF 导出耗时不超过 10s（中端机型）；15s 视频抽帧（10fps）不超过 20s；解码/合成不阻塞 UI 线程（TaskPool/Worker） |

| 兼容性 | 支持 HarmonyOS 6.1.0 (API 24) 及以上；适配直板手机；深色模式跟随系统 |
| 隐私 | 全部处理本地完成，不上传任何素材；除系统选择器外不申请额外敏感权限 |
| 存储 | 临时文件使用应用沙箱缓存目录，导出完成或页面退出后清理；历史记录计入应用空间并在系统设置中可清理 |

## 7. 技术风险与可行性

| 风险 | 说明 | 应对 |
|------|------|------|
| 系统不支持动态 GIF 编码 | 系统 `image.ImagePacker` 仅支持 JPEG/PNG/WebP 静态编码，不支持多帧 GIF89a 编码 | 自研纯 ArkTS 的 GIF89a 编码器（LZW 压缩 + 颜色量化），量化采用中位切分法，先实现 256 色全局调色板，再演进局部调色板 |
| GIF 解析（编辑功能） | 编辑已有 GIF 需要 GIF89a 解析器（LZW 解压 + 帧合成 disposal 处理） | 与编码器同源研发，LZW 编解码共享查表实现；disposal 处理先支持最常见的整帧覆盖模式 |
| 视频抽帧性能 | 15s 视频软解抽帧耗时与内存压力较大 | 使用系统 AVCodec 解码 + 时间点采样，只解码目标时间帧；限制片段 15s、帧率 24fps 上限；后台任务执行并支持取消 |
| 大图内存压力 | 多张 48MP 照片解码后内存爆炸 | 选图后立即按目标输出尺寸下采样生成帧位图，原始大图不驻留内存 |
| 叠加层渲染 | 贴纸/文字需在导出时逐帧渲染进位图 | 统一用 Canvas 离屏绘制：每帧 = 底图 + 全局叠加层列表按 z 序绘制；预览复用同一渲染管线保证所见即所得 |
| 合成耗时 | 像素级量化 + LZW 编码在 ArkTS 中较慢 | 编码放入 TaskPool 后台任务；提供进度回调与取消机制；480P 以下档位优先保障流畅 |
| 帧时长精度 | GIF 帧延迟以 10ms 为单位存储 | 帧时长步进设为 0.05s（50ms），倍速档位设计为 50ms 的整数倍约数，避免精度丢失 |

> 结论：核心链路（选素材 → 下采样/抽帧 → 叠加渲染 → 量化 → LZW 编码 → 保存）技术上可行，主要工作量在 GIF 编解码器、视频抽帧与性能调优，建议先做 480P/256 色的竖切验证。

## 8. 测试策略（TDD）

采用"核心算法 TDD、UI 验收驱动"的混合模式。

### 8.1 适用范围

| 层次 | 是否 TDD | 说明 |
|------|---------|------|
| GIF89a 编码器（LZW、量化、帧延迟编码、块结构） | 是 | 纯函数式确定性逻辑，输入输出明确 |
| GIF89a 解析器（LZW 解压、帧时长/循环数读取） | 是 | 同上，且有标准文件可做基准 |
| 帧逻辑（时长步进/覆盖/倍速叠加、倒放与来回重排、2~30 张边界、下采样尺寸计算） | 是 | 不依赖 UI 即可测 |
| 抽帧采样计算（时间段 → 帧时间点序列） | 是 | 纯计算逻辑 |
| 页面 UI、预览播放、系统选择器、保存/分享 | 否 | 依赖系统组件与真机交互，用验收标准（第 9 节）+ 真机走查覆盖 |

测试基础设施复用 hypium，参照 `entry/src/test/SudokuCore.test.ets` 的本地单测模式。

### 8.2 具体策略

1. **先写测试清单再实现**：第一阶段输出即为可执行测试集，将第 3.5/3.6/3.7 节规则转译为用例（红 → 绿）；
2. **golden file 字节级基准**：用 ImageMagick/ffmpeg 预生成标准 GIF（单色 1×1、双色渐变、多帧不同延迟），关键结构（文件头、逻辑屏幕描述符、Netscape 循环块、帧延迟值）逐字节断言；
3. **解码回环验证**：不逐字节对比整个产物，而是用自研解析器（或测试专用简易 parser）回读产物，校验帧数、每帧延迟、循环次数、像素抽样一致性——比 golden file 更抗编码器实现的合理差异，同时交叉验证编解码器；
4. **边界用例**：纯色图（量化退化）、超 256 色图、0.25x~4x 倍速与 50ms 存储值的换算、来回模式首尾帧不重复、15s/24fps 抽帧上限、2 帧下限与 30 帧上限。

## 9. 验收标准

1. 三种模式（图片合成 / 视频转 GIF / 编辑 GIF）均能走通"选素材 → 编辑 → 预览 → 导出"完整流程；
2. 调整倍速、帧时长、播放模式、播放次数、输出尺寸后，预览效果与导出文件一致；
3. 导出的 GIF 可在系统图库正常播放，帧序、帧时长、循环次数与设置一致；倒放/来回模式的帧顺序正确；
4. 播放次数为"循环"时 GIF 无限循环；为指定次数时播放完静止在最后一帧；
5. 视频转 GIF：截取片段的实际时长误差不超过 ±0.5s，抽帧数与所选帧率一致；
6. 编辑已有 GIF：原帧时长与循环次数被正确读取并带入；叠加的文字（含自定义颜色）与贴纸正确渲染进导出产物；
7. 制作历史：导出后生成记录，可预览/保存/分享，删除后记录与沙箱文件同时清除；
8. 合成过程中切换后台、旋转屏幕、点击取消，应用不崩溃且状态正确恢复/终止；
9. 帧数 < 2 时无法导出；图片超过 30 张、视频片段超过 15s 时被正确限制；
10. 断网状态下完整流程可用（纯本地）；
11. 深色模式下页面无不可读元素。

### 11.6 已知限制

- "原始尺寸"档位当前长边上限 720px（内存安全；多帧 RGBA 像素缓冲最大约 80MB），480P/720P 档不受影响；后续可通过流式解码解除。
- 各帧宽高比不一致时以最大帧为画布基准、白底留白对齐（F61 的"以最大帧尺寸为基准"）。
- GIF 拆帧与视频抽帧在 UI 线程以 await 驱动（系统解码在原生层执行，逐帧让出事件循环），未迁移 taskpool；抽帧遮罩期间可取消，长片段表现待真机验收。
- GIF 解析按白底不透明合成（与导出行为一致）；带透明背景的 GIF 重导出后背景为白色。
- 视频抽帧为时间点采样（AV_IMAGE_QUERY_CLOSEST），帧间隔均匀但可能落在最近关键帧附近，与源视频逐帧存在细微时序误差。
- 叠加层渲染依赖 `drawing.Font` 系统 emoji 字形：彩色 emoji 在部分设备上可能以单色轮廓渲染（无真机验证）；导出侧逐帧 `renderOverlaysIntoPixels` 在主线程执行（30 帧 480P 约多耗 1~2s，进度提示"合成中"）。
- 历史记录的"参数摘要"为文本展示，不支持一键回填再编辑（F103 P2）；历史 GIF 文件存于应用沙箱，卸载应用即清除。
- 预览画布盒内帧与叠加层为分别的组件叠加，逐帧切换时叠加层静止（与导出一致）；未做叠加层逐帧关键帧差异动画（P2）。
